1.1 Message Authentication
HIGH
Definition: The process of verifying that a message is authentic — its contents are unaltered, it came from an authentic source, and it is timely and in correct sequence.

Key Concepts

  • Protects against active attacks
  • Can use conventional encryption (only sender & receiver have key)
  • Or use separate MAC appended to cleartext
  • MAC formula: MAC_M = F(K_AB, M)

Real-World Example

When your bank sends you an OTP or when an email client checks DKIM signatures — these verify the message hasn't been tampered with and truly came from the claimed sender.

1.2 Secure Hash Functions
HIGH
Definition: A function H that maps a variable-length input to a fixed-length hash value (digest), satisfying specific security properties.

Requirements (MEMORIZE ALL 5)

  • 1 Works on any size data
  • 2 Produces fixed-length output
  • 3 Easy to compute H(x) for any x
  • 4 One-way: infeasible to find x given H(x)
  • 5 Weak collision resistance: infeasible to find y≠x with H(y)=H(x)
  • 6 Strong collision resistance: infeasible to find any pair (x,y) where H(x)=H(y)

Exam Point

SHA-2 family (SHA-224/256/384/512) is currently the standard. SHA-512 uses 64-bit operations. MD = Message Digest.

1.3 Digital Signatures
HIGH
Definition: An encrypted message that can be mathematically proven to be authentic. Created using asymmetric (public key) encryption.

How It Works

Sender hashes the message → produces digest

Digest encrypted with sender's private key → digital signature

Message + signature sent to receiver

Receiver decrypts signature with sender's public key

Receiver hashes message independently and compares — if match, authentic!

Properties Provided

  • Authentication Verifies sender identity
  • Non-repudiation Sender can't deny signing
  • Integrity Message not tampered

Real-World Uses

  • E-mail (S/MIME, PGP)
  • Code signing (Windows drivers)
  • E-commerce transactions
  • Legal documents
